## Runtime and native boundary

The runtime bridge changes four files: the managed icall declaration and
registration, interpreter execution guards, and interpreter transformation
observations. The native runtime changes twelve files around code-generated
invoke guards, transaction/execution diagnostics, type keys/resolution,
metadata class materialization, reflected method canonicalization and
`Runtime::Invoke`.

`AssemblyShadow::AssertMethodIsActive(const MethodInfo*, const char*) noexcept`
rejects physical baseline candidate methods before supported execution paths.
The guard does not remap a baseline method to a patch body. It preserves the
first failure and uses stable code `BaselineMethodExecution = 21` in both native
and managed enums. Direct ordinary nonvirtual AOT calls are still excluded by
closure and fixed-AOT policy rather than a per-method dispatch stub.

Execution observations are separate from the historical transaction and type
diagnostics. They count actual checks, class-initializer starts and successful
interpreter transformations. Class storage pointers are Development diagnostics
only; Release emits no pointer details. Observation collection must not create a
class or run a class initializer.

All return `AssemblyShadowErrorCode`. Editor and Mono throw

## Package generator and policy boundary

The package adds explicit byte-bound generation inputs instead of treating a
list of assembly names as provenance:

- `ShadowGenerationPlan` freezes target, architecture, source pins, compile
  snapshot, ordinary inputs, closure/load order, resolver catalog and hashes.
- `ShadowGenerationAotInputs` freezes the actual stripped-AOT provider set and
  selected-candidate exclusions.
- `ShadowGenerationOutput` records Link, MethodBridge and AOT-generic outputs,
  their generated bytes, ABI signature inventories, resolver catalog and
  emitted assembly names. Coverage is checked against P01/P02/P03 before a
  selected P03 output can build the Player.
- `ShadowWarmupManifestReader` preserves schema-1 patch compatibility and reads
  the explicit schema-2 envelope. `ShadowWarmupValidator` binds unambiguous
  assembly/type/method signatures to the verified closure.
- `ShadowExecutionPolicy` and the compiled Editor inventory reject fixed
  Bootstrap candidate generics, candidate P/Invoke/Burst boundaries, early
  runtime initialization, preloaded candidate assets and execution-order
  dependencies that can precede the Bootstrap.

MethodBridge, reverse-PInvoke, AOT generic and link generation consume the
verified resolver rather than a mutable search directory. Ordinary generator
menu defaults and the Player hot-update assembly filter remain unchanged.

The five immutable generation plans are `Ordinary`, `P01`, `P02`, `P03` and
`InitializerFailure`. P01 shadows Internal; P02 shadows Extensibility, Internal
and ExtensibilityConsumer; P03 shadows all five business assemblies in

The Bootstrap boundary has no compile-time candidate reference. It verifies the
fixture, baseline, Player, generation, type and execution proofs before the
first Shadow API call, loads required supplementary AOT metadata, commits,
runs module initializers, applies the finite warmup dispatcher, then performs
business observations. Runtime MVID is intentionally unavailable; byte-bound
offline MVID/token/PDB evidence remains separate.

The exact 28 fresh-process modes cover constructor/statics P01/P02/P03, mixed
P01, inheritance P02, full P03, delegate/event, generics/structs, async/iterator,
initializer failure plus separate baseline recovery, warm/no-warm P01/P02/P03,
native-OFF, and a genuine Release/no-PDB case. The strict verifier independently
recomputes expected business values, identities, state/diagnostic sequences,
method metadata, generation provenance and transformation deltas; a launch
receipt alone is diagnostic rather than acceptance.

## Retention and limits

The M06 Evidence archive retains every final Player result/diagnostic/log,
complete Development and Release fixtures, all generation plan/output receipts
and generated outputs, selected Player-input proofs, and the fresh closeout
suite. Reproducible multi-gigabyte compile/IL2CPP workspaces and Player apps stay
at immutable local paths and remain hash-bound by copied receipts; the retained
copies are not a portable or authenticated deployment.

Coverage is pinned to macOS ARM64, Unity 2022.3.62f2 and the recorded source
revisions. Native adapters and finite acquisition scanners are not a proof of
every platform or arbitrary whole-program reflection flow. Timings distinguish
transformation observations from wall clock and are not production performance
claims. M07 resource/Unity-asset integration remains outside this boundary.
