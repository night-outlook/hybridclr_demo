## 1. Goal, boundary and successful outcome

**Objective:** replace the D1–D4 native-host substitutes with source-authenticated, *real* Unity 2022.3/IL2CPP production build and Player evidence, while preserving every original source pin, first-error invariant and historical receipt. The D5 Local Validation Agent may reproduce, diagnose and make only bounded, locally closed unblock fixes **after explicit authorization and a fresh committed WEB_TO_LOCAL handoff**. Non-trivial production/harness changes return to Primary Implementation.

D5 completion is **not** synonymous with shipping/release, H2, or acceptance. D5 evidence must independently establish or explicitly mark `NotRun/Blocked/NoCoverage` for native compilation/linkage, actual process execution, original V1/B1/R02 compatibility, owner lifetime, P0–P6 ordering, failed publication terminality, cross-thread method admission, GC/VM shutdown, and platform ABI. The later D6 Human Review Gate decides full stage closure.

**Preapproved source-host evidence is not Local evidence:** D4 exact-code CI [44517874612](https://github.com/night-outlook/hybridclr_demo/actions/runs/44517874612), **attempt 2**, 4/4 success at demo code `c3307abacaaaec9db2a0f866b726e2ae5df1108b`; 80 source tests, 176 host receipts/3,580 assertions and four expected-failing test-only owner controls. Nothing here claims the full `AssemblyShadow.cpp` production translation unit was linked in a real Player.

**D5-B — Proposed dry admission (Local, only after explicit D5 Local authorization).** Authenticate physical local Git roots, clean HEAD and canonical remotes, original S, Unity 2022.3.62f2 executable hash, macOS/Xcode/SDK/architecture, disk space, output paths and source SHA list. Verify native install/generator source roster, config and all test fixture inputs; create a fresh, external one-use receipt root *only after* all read-only admissions pass. **D5-C — Actual native build/link (Local, authorized only).** Fresh isolated Unity 2022.3.62f2 macOS arm64 IL2CPP **feature ON/Release** build first; feature OFF/Release as negative/control on a separate fresh project and output. Capture actual BuildReport result/errors/warnings, Editor.log, Unity/Mono/compiler tool versions, installed `libil2cpp`/HybridCLR source manifests, generated C++, Bee DAG/compile commands, architecture, native image UUID and SHA-256, link symbols, IL2CPP flags and BuildPipeline output. Do not infer compilation success from source-host CI; do not launch Player if the source build/roster proof fails. Negative control verifies no host allocator overrides and no unexpected source extras.

**D5-D — Player behavior/fault cells (Local, authorized only).** Use a separate process for each negative or post-Codec failure; never attempt an in-process reset/rollback after terminal publication. Include healthy P0→P6→Complete, old V1/B1/R02 byte/provenance checks, P0 used-closure refusal, P1/P2 non-Codec failures, P3 real Codec validation refusal, P3 unknown/exception result, P4 Runtime group-active then failure, P5 after `s_active` store, P6 initializer failure/exception and first-error survival, repeated post-terminal business method attempts and GC/shutdown. **Failure injection is `NoCoverage` until a specific real-Player diagnostic producer exists, has a source-pinned receipt and is separately reviewed; a mock-host result is not a Player test.** For post-Codec faults, preserve terminal state, no baseline fallback, unchanged canary, non-retryability, and first-error origin. Validate any concurrent reader/business method around P5/P6 using deterministic barriers with real method-entry gates and zero unsafe release-mode data races.

**D5-E — Platform/ABI and source parity (Local, additional target approval as needed).** On macOS arm64, inspect real ABI and atomic properties. A 32-bit native target/Player and other OS targets are separate explicit builds; if missing, record `NotRun` rather than speculating. Compare V1 fields14/15 and B1/V2 first-event recovery output exactly as defined in existing source, and keep R02 counters/TypeDef identity/caps unchanged. Only assert `Pass` for cells actually executed against the linked target binary.

**D5-F — Evidence publication, independent full-stage review (Local and independent reviewer).** Finalize immutable per-command stdout/stderr, raw Player logs/JSON and sha256 artifact ledger, return a signed-by-provenance (not cryptographic signature assertion) `LOCAL_BATCH_RESULT.json`, update `LOCAL_VALIDATION.md`, record blocking/nontrivial findings in `RETURN_TO_WEB.md` and push selected receipts to Git. Independent review compares real evidence to the exact source/Unity/Player manifest, not just a pass count. `ReturnRequired` flows back to Primary for nontrivial fixes. D6 Human Review Gate requires its own explicit human decision and is not entered automatically.

## 5. Evidence custody and stop conditions

All artifacts should be under a **new absent** absolute root outside the entire four-repo workspace and every repo/worktree root, proposed pattern `/Users/ah/GitHub/r03-local-validation/R03-B2-D5-<unique-oneuse-id>`. The pattern is illustrative; the Local agent must prove that the chosen path is physically canonical, does not exist and is disjoint from source/historical roots. Reusing historical `oneuse-12`, prior product roots, symlinked aliases or existing Player outputs is prohibited.

Every test cell must report `Passed`, `Failed`, `Blocked`, `NotRun`, `Unavailable` or `NoCoverage` with exact condition, source/Player SHA, PID/exit where applicable, phase and reason, first error, native registry/codec/owner state (where observable), evidence files and source type (`RealPlayer`, `ExactNativeHost`, `Synthetic`, `SourceOnly`, `HistoricalComparator`). **Never promote `Unavailable`, `Blocked`, reused historical data or a synthetic stand-in to a real-Player `Passed` result.** Evidence products must reject unexpected symlinks and mutable replacement; use explicit raw material/ledger and no overwriting receipts.

A mandatory release stopper is any build/Player crash, wrong source/ABI, observable method entry after a terminal flag, first-error replacement, public snapshot freed while readers remain, unhandled exception after P5 that leaves a nonterminal state, prior source-roster corruption, or uncertain P3+ rollback. These produce `ReturnRequired` or `Blocked` and no R03 approval. If a diagnostic scenario itself cannot be produced in the target, mark `NoCoverage`, not Pass.
