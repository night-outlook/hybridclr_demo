## 4. Finding IR-D5BC10-RR3-01 — HIGH / blocking: no pre-entry state/failure witness; preexisting terminal denial can be misattributed to the P5 policy

The target [`R03_D5_BeginKeepAttempt`](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/R03D5WindowOverlay.cpp#L572-L589) arms a one-shot method pointer and P5 phase token, but **does not record native `AssemblyShadowState` or immutable first-error status at the actual method guard entry**. The actual [`AssertMethodIsActive` early-return logic](https://github.com/night-outlook/il2cpp_plus/blob/c741fb32a2b770856f211f47305c4f86b51f54ce/libil2cpp/vm/AssemblyShadow.cpp#L2324-L2352) now deliberately counts a correct target denial **when `TerminalMethodDenied(method)` was already true**. A denial because the process was already in `FailedAfterCommit` therefore has the same `TargetDecision=2` as a rejection that arose from the current P5 attempt.

The [collector](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/R03D5WindowOverlay.cpp#L320-L372) samples `GetState` **after** the guard, then emits slot 6 with that later state and freezes the current first-error bytes. The [receipt classifier](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/d5_c10_native_receipt.py#L102-L133) requires only post-event state `9`, P5 observation, a single target-denied counter, canary unchanged and *some* frozen first error; it does not join the first error's epoch/origin to the target attempt or require `Committing` and absence of a prior terminal error **at the actual target guard entry**.

The intended [D5-C10 source plan](D5B_REAL_PLAYER_PRODUCER_AND_LINK_PLAN_2026-11-20.md) specifies a **healthy, concurrently active P5→P6 method-entry window** after UsageLock release and before initializers. If the process was already poisoned by an unrelated earlier terminal event, a subsequent target `Keep` denial is a different terminal-guard negative. It cannot by itself establish the **healthy P5 admission policy**. Source-only tests merely mock `state=9` and an already frozen error for the denied scenario. They do not distinguish *preexisting terminal* from *terminal resulting from the target attempt*. The classifier label `CandidateObservedDeniedInP5_RequiresIndependentBinaryProof` is still only a candidate and **does not mark a real Player Passed**, but this missing distinction makes it ambiguous evidence for its intended C10 purpose.

**Correction:** bind an allocation-free, exact TLS target guard-entry witness to native `P5` phase, native state (`Committing` vs `Failed/FailedAfterCommit`), and first-error status **before** invoking the first terminal policy check. Preserve the existing deny behavior and first-error custody. Record preexisting terminal as a **distinct terminal-negative/NoCoverage** state, not a healthy P5 denial candidate. Add deterministic source-host counterexamples for a process already terminal before Keep, a healthy `Committing` P5 entry that then becomes terminal, and a P5→P6 race. Do not infer entry state from a post-guard `GetState` call or from the presence of a frozen first-error alone. The full native VM path remains NotRun.

## 5. Finding IR-D5BC10-RR3-02 — HIGH / blocking: synthetic evidence claims worker completion without observing any worker completion

The [native autonomous collector](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/R03D5WindowOverlay.cpp#L215-L225) writes slot 6 as `Record(6, -1, stateCode, 1, TargetArmCount())`. The literal **`1`** occupies the third payload position used by the still-present [manual receipt API](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/R03D5WindowOverlay.cpp#L593-L613) for `workerFinished`. No `Thread.Join`, managed completion observation, or acquired `ReleaseP5` is required on the **denied** path. Yet the [classifier, lines 102–112](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/d5_c10_native_receipt.py#L102-L112), requires `observed[6][2] == 1` to classify a denied candidate.

This is **not merely theoretical**: the exact [`D5AutoReceiptHost.cpp` lines 55–94](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/D5AutoReceiptHost.cpp#L55-L94) calls `ReleaseP5` **only for `allow``, not `deny`. Nevertheless all four raw job logs emit `PassedSyntheticNativeAutoCollectorReceipt strict denied CandidateObservedDeniedInP5_RequiresIndependentBinaryProof` and the equivalent sanitized line. The [receipt tests](https://github.com/night-outlook/hybridclr_demo/blob/dbb1360c5b68dabab05755a5d39a5cea53270574/Tools/AssemblyShadow/R03IR/D5Probe/test_d5_c10_native_receipt.py) simultaneously contain `test_17_worker_unfinished_not_denial_proof` (mutate the third slot-6 value to zero ⇒ NoCoverage) and `test_28_native_auto_writer_without_finished_managed_worker` (requires the positive candidate **without managed worker completion**). A source fixture can thus satisfy a supposed "worker-finished" requirement using a **constant emitted by the recorder**, not an observed fact.

The target guard's actual denial and native first-error **can** be meaningful without managed worker completion—terminal poison is precisely why a post-terminal managed join cannot be required. The defect is the **misrepresented event-schema semantics and self-validating predicate**, not proof that Keep actually executed. A test producer must not present an unobserved managed-worker lifecycle fact as positive evidence.

**Correction:** explicitly version the slot-6 schema so it distinguishes **native collector/seal completed** from **actual managed worker completed / unknown**, or drop the worker-finished predicate entirely and require an independent native same-token guard-completion witness (already available at slot 5). Preserve native-only terminal evidence collection, never require managed post-poison callbacks. Update the contradictory `test_17` and `test_28` expectations, add a "guard denied but worker never finishes" negative/diagnostic or a correctly named native-only candidate case, and ensure the classifier cannot infer managed completion from a constant. Do not merely change the test labels without fixing what the fields mean.
