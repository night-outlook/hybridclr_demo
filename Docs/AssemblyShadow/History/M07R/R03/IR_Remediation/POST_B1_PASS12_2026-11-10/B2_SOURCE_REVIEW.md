## Blocking observations

1. **B2-SRC-01: canonical field producer not ready.** The original slot14/15 values are *complete general and execution diagnostics*, not `FirstErrorV2` data. The existing bounded P1 sources are explicitly inactive or are limited to empty execution/observed subset without full class pointer/metadata lifetime and canonical TypeKey guarantees. A real V2 writer cannot claim compatible `finalDiagnostics` / `finalExecutionDiagnostics` if it copies only B1 code/reason, replaces them with null, calls allocationful V1 getters after terminal, or reinterprets a limited P1 census as full diagnostics. **Owner: Primary Implementation.** Required next work: identify and complete the actual bounded source/lock/metadata reader for each full field, or explicitly renegotiate a separately versioned reduced schema before writing a non-compatible artifact.
2. **B2-SRC-02: host-source compiler gate corrected / B2 real SDK NotRun.** The original C++11 test *did* fail on the original header and host aggregate initialization. The Primary-owned corrections now PASS both macOS and Ubuntu in C++11/C++17 compiler jobs and all strict/sanitized actual native wire/POSIX hosts. See [B2 C++11 remediation and exact RED/GREEN receipts](B2_CPP11_COMPATIBILITY_REMEDIATION.md). This is not a compiled official Unity V2 Player or a claim of true V2 transport.
3. **B2-SRC-03: VM epoch/lifetime coverage incomplete.** General and execution getters collect under multiple disjoint locks and dereference class metadata after the observation lock. A snapshot built from independently bounded components may be useful, but without coherent VM barrier it must be described as **per-component/source-fenced**, `wholeVmEpoch=NotProven`. B2 writer must not claim global atomicity; B3 remains separate.
4. **B2-SRC-04: durability vs authenticity boundary.** Existing POSIX component can seal two native files and its reader can verify them, but the caller must build exact externally authenticated run/process/source/SDK/MVID identity and provide an immutable *independently verified* receipt. A successful binary hash alone is insufficient.
