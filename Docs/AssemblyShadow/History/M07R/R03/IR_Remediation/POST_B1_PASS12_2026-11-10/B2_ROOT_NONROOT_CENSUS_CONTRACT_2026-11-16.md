# R03 B2 — root/nonroot TypeDef census contract (source-host only)

**Date:** 2026-11-16 UTC. **Stage:** Primary Implementation. **Branch:** `codex/assembly-shadow-r01b-h1`. **Native baseline:** `night-outlook/il2cpp_plus@cecf4b859d50b128e5c0fc6c90cd89e3a452b96a`. **Scope:** an **offline analyzer and source-capture contract**, not native collection, Unity evidence, storage selection, or runtime integration.

## Source anchors and why a census is needed

- `libil2cpp/vm/AssemblyShadowBoundedDefinitionExecutionLiveSource.inl` performs the inactive B2 physical enumeration while the initial `assembly_shadow_metadata_lifetime::Gate::Reader` and `g_MetadataLock` are active. It observes up to **1,024 physical class identities**. Distinct root handles are preflight-capped at **129**, but this preflight excludes nested/generic/primitive nonroot TypeDef uses.
- `AssemblyShadowBoundedDefinitionExecutionLive.h` currently caps the **combined** root + nonroot first-owner/content audit at **128 distinct TypeDef handles**, with **64 bytes per namespace and simple-name field** and up to **65,536** indexed owner lookups. A rejected source may preserve only its root-only capped diagnostic; positive counts are scrubbed.
- `AssemblyShadowOriginalV1OwnerJoin.h` documents the original field15 first-emplace rule: iterate token-valid physical images in the original `CopyValidAssemblies` order, and use the *first* image containing each exact TypeDef handle. This is distinct from comparing image pointers or accepting the most recent owner.
- `AssemblyShadowMetadataLifetime.h` admits an initial-source-epoch reader (epoch **1**) by default and drains readers before Runtime shutdown. It does **not** prove that registered `Il2CppClass*`, `Il2CppType*`, metadata or GC-managed objects share a coherent VM epoch; its comment explicitly warns against substituting a gate epoch for source provenance.
- Separate test-only candidates in `hybridclr_demo/Tools/AssemblyShadow/R03IR/CapacityCandidates/` have a bounded Patricia index and fixed/compact preallocation. Their 1,024-record and ABI results are **synthetic**, not evidence that raising native B2's cap is safe.

A credible capacity decision requires a **real, uncapped, root + nonroot high-water census** from the same authenticated source session. Existing successful/capped B2 receipts cannot supply that population.

## Proposed upstream trace contract (NOT implemented)

The analyzer accepts one UTF-8 JSON object with exactly `schema`, `captureKind`, `source`, `events`. `schema=R03B2TypeDefCensusV1`, `captureKind=Synthetic|UnverifiedSource`. The source object must supply branch and exact 40-character demo/native commit SHAs; a claimed initial reader epoch=1, `metadataLockHeld=true`, original V1 image count, three class passes, two original V1 image passes, observed class count, declared event count, dropped event count and a boolean `complete`.

Each event must record an opaque **per-capture temporary `handleId`** (not a raw address or a hashed identity interpreted across sessions), the physical `ownerImageOrdinal`, the *independently determined* `firstOwnerImageOrdinal` from original field15 order, **one explicit role** (`root`/`nonroot`), `namespaceBytes`, `simpleNameBytes`, `declaringIndex`, `genericIndex`, and `arity`. A handle used in both roles has two events and one distinct record. An owner mismatch or declaration drift rejects the trace. Unknown fields, duplicate JSON keys, invalid numeric types, nonfinite JSON, oversize input and apparent false completion reject rather than produce a result.

**Important:** A JSON field stating `metadataLockHeld=true`, `complete=true`, or `captureKind=UnverifiedSource` is *not proof* of any fact. `StructurallyCompleteUnverified` means only that the supplied inventory is internally consistent. The 16 MiB JSON/200,000-event parser guard is a *tooling* limit, not a production collector allocation budget. The reported 64-bit numbers use previously measured candidate layouts: fixed slab **(160+32)×N**; compact **(40+32)×N+sum(name lengths)** at capacity N. Neither includes allocator bookkeeping, future capture buffers, lock time, VM stack/RSS, metadata ownership or unused arena headroom. All capacity flags are observations, never recommendations or product admission.

## Contract for a future native census source

1. **Entry and lifetime.** The inactive source is entered only with an independently admitted initial-epoch MetadataLifetime `Reader`, under the actual `g_MetadataLock`. No source pointer is dereferenced after releasing either protection. Epoch=1 is necessary for today's source but not sufficient for class allocation, GC or VM-wide lifetime. Native inspection must establish the precise callback/registration lifetime and owner backlink for every recorded class and TypeDef.
2. **Uncapped coverage before selection.** Independently enumerate every root from the first physical callback **and** every TypeDef argument reached by the actual `TypeKey` construction paths (generic parameters, nested declarations, primitive defaults and supported composite forms), including *otherwise rejected* shapes. Record excluded/unsupported categories and overflow; do **not** infer complete coverage from the current <=128 audit or a root-only 129 preflight. The recorder must fail closed on unknown categories or loss. Distinguish use-role from handle equality.
3. **Source identity.** Assign ephemeral handle ordinals within a single capture. Confirm each exact indexed handle's first-emplace original V1 image owner in token-valid image order. Record declaration namespace/simple-name **byte lengths** and metadata indices while borrowed source remains protected; never log/export pointer values or borrowed strings. If full UTF-8 byte copies are separately required for drift analysis, specify and independently review their memory and privacy envelope before collecting them.
4. **Bounded overhead and cleanup.** Reserve every recorder buffer before `g_MetadataLock`; no file IO, unbounded traversal, per-event allocation or text formatting while holding the lock. Define a hard upper bound for temporary IDs, event cardinality, owner lookups, name lengths, worker stack, lock time and failure scrub. When any bound is exceeded, return `Incomplete` plus a lower-bound count, **not** a successful census or allocation decision.
5. **After-lock evidence.** Only after synchronously copying and finalizing protected source facts may a separate output step write the trace. Bind source commit tuple, Unity/IL2CPP build identity, raw evidence hashes and actual run provenance in an independent receipt. The offline analyzer's JSON cannot authenticate these; a separately reviewed audit must establish all provenance. Never reuse B1 oneuse-12 as B2 evidence.
6. **Selection gate.** Establish observed root+nonroot distinct high-water and roles, name-length tails, first-owner conflicts, unsupported shapes and lock/lookup cost *on real source*; rerun under relevant platform/scene coverage. Only then compare the fixed-slab and compact candidates against actual max cases and the 65,536 lookup limit. Require a **new explicit Human Review Gate** and independently authorized Local Validation before changing the native 128 cap or attaching the preallocated candidates.
