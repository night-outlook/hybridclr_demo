## 2. Actual new producer semantics

1. Under the initial-session `MetadataLifetimeGate::Reader`, take **two independent copies** of the original process-lifetime `s_executionClasses` and registration-witness table under **one** `ExecutionObservationLock`, preserving the original registry revision.
2. Under **one enclosing `g_MetadataLock`**, execute the actual physical class enumerator **first** for observed-class physical matching. Only `FirstMatch` callbacks may dereference `klass->image` and contribute to a bounded unique-image inventory. An unregistered class cannot supply an owner image. Reject duplicate/unmatched callbacks, interpreter images, missing image identity, more than 64 unique images or missing owner data.
3. Still under that metadata lock, run the physical class enumerator **again** to collect rows. For each metadata TypeDef handle, search *only* the admitted first-pass AOT image handles using `MetadataCache::GetAssemblyTypeHandle`. Prove exact pointer membership **before** dereferencing `Il2CppTypeDefinition`. A missing owner is `UnadmittedMetadataOwner`; one handle resolving to two distinct images is `AmbiguousMetadataOwner`; a definition's nested declaring chain must remain inside its verified owner image.
4. For `GENERICINST`, keep the observed class's definition bound to its own physical image, but admit a concrete `CLASS/VALUETYPE` argument from a *different* image **only** if another observed class's first-pass callback independently admitted that argument image. The canonical argument key uses **its own image's assembly name**, not the observed generic definition's assembly. Preserve original UTF-8 byte length prefixes, declaration order, and generics definition arities.
5. Copy bytes and class primitives into the previously tested bounded immutable rows and original native frozen execution/R02 serializer. At most **65,536 total metadata-handle comparisons**, **8,192 TypeDefs per inspected image**, **64 observed image owners**, **16 generic arguments** and **4,096 bytes per key**. Fail closed on overflow; no partial output is admitted.
6. Verify the original R02 and registry/source fences and reject an originating B1 terminal error. Clear the callback's image-inventory pointer before the metadata lock scope ends. The borrowed-image inventory's destructor scrubs its entries before releasing the lock; no extra image handles are exposed to a caller.

**Explicit limitation:** Source coverage extends only to AOT images with an *independently matched observed class*. It does **not** allow an argument from an unobserved physical image, even if that image exists in the global assembly table. Neither two passes nor unchanged registry/counters establish a whole-VM epoch. There is no normal application or Player caller and no postterminal field15 support.

## 4. Remaining blockers and next Primary step

- **B2 field15 completeness:** The observed-class inventory is intentionally incomplete for images without a matched class. Other generic shapes (`GENERICINST` of `GENERICINST`, array/pointer, open `VAR/MVAR`, qualifiers, Unicode assembly folding) and exact legacy V1 byte parity on real classes remain unproved.
- **Lifecycle and source consistency:** The initial metadata Reader blocks teardown only for its original session. It cannot authenticate real class allocation provenance, class cctor/storage mutations, arbitrary GC races or a VM-wide atomic timepoint. The physical enumerator itself may allocate and runtime performance/lock duration is unmeasured.
- **B2 field14 and transport:** No complete, terminal-safe `finalDiagnostics`, full `finalExecutionDiagnostics`, independently authenticated native V2 descriptor binary/envelope/receipt or actual first-recovery Player test yet. Original-S missing custody, R03 High findings and B3 epoch/GC/RSS/RC/P/E remain open.
