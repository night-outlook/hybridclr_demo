## 1. Source baseline and design selection

The canonical feature branch is `codex/assembly-shadow-r01b-h1`. Native runtime source was **not edited**: `night-outlook/il2cpp_plus@8aa8d09319a89b55b2496bcc2c69ccc69cb57be9`. The original `AssemblyShadowTypeKey.cpp` computes a metadata definition key through `ShadowTypeKey::ToString` using `type(` plus byte-length-prefixed canonical assembly and outer-to-inner declarations (`/len:namespace/len:name@arity`), and `FormatMetadataOnly` formats generic/constructed/qualified types through additional cases. `AssemblyShadowName.h` specifies UTF16 case folding, not locale-dependent ASCII case folding, for physical assembly names. The original `AssemblyShadowExecutionSerializer.h` is the same source used by the allocationful legacy execution getter and by `AssemblyShadowFrozenExecutionRecord.h`.

The existing source evidence *does not* prove class pointer origin: `TryCaptureOwnedObservedPhysicalNames` returns only physically matched borrowed display bytes/shape, explicitly **not** canonical TypeKeys; `TryCaptureBoundedEmptyExecutionLive` rejects a nonempty class set. Full `finalExecutionDiagnostics` (V2 slot15) is still incomplete. See [B2 VM source-readiness gate](B2_VM_SOURCE_READINESS_GATE.md).

**Design decision:** create separately owned, preallocated, bounded **test-only** components under `Tools/AssemblyShadow/R03IR/NativeDiagnostics/`. Verify the legacy TypeKey subset grammar, class-row ownership/order and the **actual native C++ serializer and frozen record**, without modifying the original native VM, its baseline source pins or the previous oneuse-12 test overlay. Explicitly reject unsupported shapes, capacity and stale inputs. A successful pure formatter/row/frozen record is *not* a physical VM-source admission.

## 4. Independent implementation assessment (Primary)

- **PASS within pure host scope:** correct bounded copying, one-shot state, no retained metadata pointer, original legacy grammar for **restricted** TypeDef subset, complete row ordering and nine flags, actual shared native execution serializer parity and actual frozen execution/R02 suffix parity with a synthetic R02 source; strict/ASan/UBSan + C++11/C++17 Mac/Linux succeeded.
- **Open high-risk source question:** existing `s_executionClasses` registration witnesses/physical iterator membership are **opaque pointer identity observations**, not proof that all observed class pointers can be safely dereferenced or their lifetime spans postterminal. The Reader defaults to the initial source epoch. A new VM adapter must hold a legitimate metadata admission ticket and use a reviewed physical enumerator callback to copy data synchronously while the source class header is valid. No pure host result can establish this.
- **Open canonical key coverage:** `FormatMetadataOnly` supports nested definitions, instantiated generic types, arrays/qualifiers and Unicode assembly folds beyond this formatter's explicitly supported subset. Tests of ASCII metadata TypeDef keys **do not** prove parity for these shapes, nor do they certify a physical TypeDef handle/owning image. Unsupported shapes must reject with a typed error, never serialize a display name instead of the original TypeKey.
- **Open field semantics:** the field15 serializer must join actual state, class cctor/storage/status bits, registry order and a complete real R02 snapshot to the correct source epoch. The field14 general source likewise needs terminal-safe V1 byte equivalence. Slot14 and slot15 cannot be replaced by a B1 summary or a reduced two-field schema without explicit, separately versioned design review.
- **Open integration:** no native V2 descriptor-relative writer connected to the real VM, no real Unity translation unit or Player revalidation, no independent first-recovery V2 authentication; B3 whole-VM epoch/GC/RSS/RC/P/E and original S remain unfinished.
