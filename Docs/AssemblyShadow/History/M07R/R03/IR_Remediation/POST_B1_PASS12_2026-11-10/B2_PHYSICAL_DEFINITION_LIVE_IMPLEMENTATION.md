The real source copies only primitive and UTF-8 bytes **inside** an authenticated physical enumerator callback. It does not preserve `Il2CppClass*`, raw metadata handles or borrowed metadata name strings after returning. The original VM class registration source is the process-lifetime `s_executionClasses`/witness table, under `ExecutionObservationLock`; the physical enumerator is executed separately under `g_MetadataLock`; the two locks are **not nested**. The initial-session `MetadataLifetime::Reader` spans the operation and admits only epoch 1. Any reused capture, unavailable ticket, changed registry/active state, missing physical match, duplicate class, unsupported image/type, missing same-image TypeDef owner, cyclic/staged/foreign declaring chain, over-budget metadata scan, counter change, incomplete row or failed frozen record invalidates the result and makes `Record::Data()` inaccessible.

**Truthful scope:** The bounded registry/counter double sample is not a full VM atomic epoch. Existing `il2cpp_class_for_each` can allocate and has no proven duration bound; this implementation makes **no no-allocation claim for the entire live VM traversal**. The owned pure serialization is bounded, but official Unity SDK translation-unit behavior is still unknown. Accepted type shapes are physical AOT `CLASS/VALUETYPE` **metadata definitions**, including verified nested definitions and generic-definition arity, **not** instantiated generics, array/pointer forms, qualified types, non-ASCII assembly case folding, interpreter metadata, or a full execution-class inventory in arbitrary projects. It is intentionally restricted to healthy-time capture: terminal `Failed/FailedAfterCommit` or B1 frozen/invalid state is a hard rejection. Thus it is **not** a complete original `finalExecutionDiagnostics` slot15 producer.
