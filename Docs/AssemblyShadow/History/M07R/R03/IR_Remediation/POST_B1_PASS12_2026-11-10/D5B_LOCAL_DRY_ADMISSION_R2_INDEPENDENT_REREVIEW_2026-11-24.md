## 3. Remaining blocking findings

### D5B-DRY-R2-IR-01 — HIGH: a failed final `fsync` can leave a complete-looking positive commit marker

**Source:** [writer `_write_locked` lines 507–520](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L507-L520) does `os.open(... O_CREAT|O_EXCL ...)`, `stream.write(_json_bytes(value))`, `flush()` and then `os.fsync()`. [The sealer lines 645–663](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L645-L663) writes `MANIFEST.json` with the **expected exact SHA-256** of the final `LOCAL_BATCH_RESULT.json`, then writes the positive `LOCAL_BATCH_RESULT.json` by this same non-atomic helper. If `fsync` or a later I/O operation on that final receipt raises **after the complete JSON bytes were written/flushed**, the file **exists with parseable positive content, potentially matching the already-persisted manifest**, although the sealer raises `PartialOutput`. It tries to write `FAILURE.json` afterwards, but [`except BaseException` lines 664–690](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L664-L690) deliberately allows that marker to remain absent if secondary I/O fails (e.g. ENOSPC). Thus a consumer comparing only expected manifest hash and final positive receipt can encounter an apparently complete product from an **unsuccessful** dry admission.

**Independent isolated host reproduction:** I reproduced the exact `O_CREAT|O_EXCL` → write → flush → `fsync` ordering with the same `_json_bytes` encoding in a temporary host directory, raising `OSError(28)` from `fsync` immediately after the complete write. **Observed:** the writer raised `OSError`, yet `LOCAL_BATCH_RESULT.json` existed, parsed to `DryAdmissionRecorded_NoUnityOrPlayer` and its SHA-256 matched the expected manifest value. This is an isolated reproduction of the source algorithm, **not an execution of the full pinned D5Local runner** and **not Unity/IL2CPP/Local evidence**. No production approval was modified. Negative [test 60](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/test_d5b_local_admission.py#L721-L746) throws **before** calling the real `_write_locked` for the target file; [test 65](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/test_d5b_local_admission.py#L839-L855) also throws before creating/writing its target files. Neither tests this after-flush/`fsync` case.

**Required Primary remediation:** make the positive success marker a two-phase, **failure-safe commit**: write and `fsync` a distinct precommit file using the already verified child directory descriptor; verify its bytes/hash; only then atomically rename/link it to `LOCAL_BATCH_RESULT.json` as the **last** visibility-changing action. Ensure a failed final durability/commit operation cannot be mistaken for a completed receipt, and define evidence verification that rejects any `FAILURE.json`, missing/partial final marker, invalid manifest or consumed-but-unsealed root. Handle the exceptional case in which a rename succeeds but subsequent directory durability confirmation fails; no false success or ambiguous manifest-only acceptance. Add synthetic tests that inject I/O errors **after the final file has received valid complete bytes** and on final marker/dir fsync, including when the failure marker cannot be written. Preserve one-use no-retry and the null production approval.

### D5B-DRY-R2-IR-02 — MEDIUM: final descriptor-close failures bypass the partial-output exception handler

**Source:** [sealer `finally` lines 692–695](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L692-L695) calls `os.close(root_fd)` and `os.close(parent_fd)` **after** the internal `except BaseException` block has completed. An `OSError` during either descriptor close can therefore override a successful `return result` **outside the sealer's `PartialOutput` translation**. The public CLI handles `PartialOutput` at [lines 733–749](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L733-L749), but a bare `OSError` is caught by the generic branch [lines 750–758](https://github.com/night-outlook/hybridclr_demo/blob/98ef93ef063c82072550357cafd9ccac72db92dc/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L750-L758), which unconditionally reports **`outputCreated=false`**, even though the directory and receipts may exist. This is a distinct remaining manifestation of the original IR-03 false-output-state defect.

**Independent host-level control-flow reproduction:** an isolated Python function with the exact `try/except/finally` structure returned a positive result from its inner try, then raised `OSError(5)` from the `finally` close operation; the outer generic handler received the raw `OSError` and reported `outputCreated=false` after the modeled root-creation flag was true. This is a **source-derived control-flow counterexample**, not a real macOS descriptor-close failure. None of the 65 tests mocks a failed `os.close(root_fd)` or `os.close(parent_fd)`.

**Required Primary remediation:** place descriptor cleanup within the same **root-created aware** exception accounting, preserving both the original write failure and any cleanup failure. If root creation occurred, a close failure must yield `PartialOutput`/`outputCreated=true` (or explicit indeterminate-after-write status requiring physical reconciliation), never a precreation denial. Add tests for both descriptor closes failing after output creation, including the case where the final receipt has already been written. Ensure close failures cannot silently produce a green success state.
