## 1. Scope and source-provenance basis

The preceding [physical TypeDef-slot upper-bound study](B2_PHYSICAL_TYPEDEF_SLOT_UPPER_BOUND_REVIEW_2026-11-17.md) established a **synthetic**, two-pass, allocation-free-in-callback counter over original-V1 physical images. It still left source admission and lock scope to its caller. The real pinned native interfaces supply two *separate* components:

- `libil2cpp/vm/AssemblyShadowMetadataLifetime.h` — **Git blob `d2fe09dd51debbbbc71d67b21347f5d971a3cafd`**. `Gate::Reader` admits the initial runtime epoch (1) by default. Its destructor drops the reader count; `Gate::CloseAndDrain` closes new admission and waits for all admitted readers. Reader admission **is not** metadata pointer allocation provenance, source generation, class/GC epoch, or a VM-wide snapshot.
- `libil2cpp/vm/AssemblyShadowOriginalV1ImageScan.h` — **Git blob `41cdb90776f1f68f3fc7cbff85045965e29b99b0`**. A pure, synchronous visitor preserves physical order and selects **nonzero assembly tokens**, retaining interpreter and zero-TypeDef images. It validates image/assembly backlink and name. It does **not** authenticate the original `s_Assemblies` vector supplied by a caller or acquire `s_assemblyLock` itself.

The exact native `Runtime.cpp@1b176ee5fd3e2127a0237877e5c9c32bc53058b3` opens the gate near the completed Init tail, before `AssemblyShadowStartup::MarkCoreReady`, and closes/drains after final Runtime Shutdown begins, before thread abort and metadata cleanup. `Assembly.cpp@df1acbfdaf054067720d2e7c1545e49100ad93ec` acquires `s_assemblyLock` around `TryVisitOriginalV1ExecutionImages` and calls the same physical scanner. These are source-order facts, **not proof of deadlock freedom, real allocation lifetime or shutdown under load**.

**This cycle never adds a Unity/native caller.** It exercises the actual above two native headers with a test-owned `Gate`, `std::mutex`, and synthetic physical-assembly vector. It does not substitute the mock mutex for `g_MetadataLock`, does not instantiate `Il2CppImage`, and does not call `Assembly::TryVisitOriginalV1ExecutionImages` in a runtime.

## 2. New code and source-boundary contract

Only `hybridclr_demo` adds three files:

1. `Tools/AssemblyShadow/R03IR/TypeDefCensus/PhysicalSlotSourceSession.h` — host-only RAII `SourceSession` accepts a **previously prepared** `PhysicalTypeDefSlotUpperBound::Census`, acquires a real **pinned native** `Gate::Reader` *before* a **mock** `std::mutex` lock, visits the actual pinned native `assembly_shadow_original_v1_image_scan::Scan` twice, and calls `Census::SealWithinSourceScope` *while* both resources are owned. Member declaration order unlocks the mutex **before** the native Reader's destructor releases admission. A denied gate, invalid/changed scan, missing pass, wrong-stage call or unclosed session calls `MarkUncovered` and scrubs borrowed opaque keys before the mock source scope exits. No allocation or formatted output in `VisitFirst`, `VisitSecondAndSeal`, or the destructor. Extractor callbacks are caller-supplied and are not proven allocation-free by this wrapper.
2. `PhysicalSlotSourceSessionHost.cpp` — synthetic physical image/assembly fixture and **12 scenario / 102 assertion** C++11 source-host suite. Tests cover closed Reader, admitted epoch 1, successful two-pass seal and scrub, abandoned second pass, changed source, invalid original backlink, exceeded image budget, duplicate registration (conservative slot upper bound), all-token-invalid source, prohibited call after seal, late `MarkUncovered`, blocked `CloseAndDrain` until the Reader is destroyed, and refusal of default epoch-1 admission after reopening epoch 2. The host output forces `realUnity=false`, `realMetadataLock=false`, `nativeSourceIntegrated=false`, `coherentVmEpochProven=false`, `R03Accepted=false`, `ReadyForHumanReviewGate=false`.
3. `.github/workflows/r03-b2-physical-source-session-host.yml` — exact commit and four native Git blobs verified before compilation; source-order checks for Reader open/close and assembly scanner under `s_assemblyLock`; two OS × two C++ standards, strict compilation and AddressSanitizer/UndefinedBehaviorSanitizer, with bounded JSON success assertions. Host tests use **test-owned mutex and Gate instance** and never run Unity or actual Player code.

This is an enforceable **test model of call sequencing**, not an authenticated VM source session. It also cannot prevent a future caller from bypassing `SourceSession` and calling the public `Census` methods directly.

## 4. Review findings, independent blockers, and next decision

- **SESSION-01 — PASS in synthetic host scope:** The Reader is acquired before the mock source mutex; capture sealing and raw identity scrub happen before unlocking; abnormal exit fails closed; a scoped Gate Reader stays counted until the session is destroyed. In the host scheduler test, a concurrent `CloseAndDrain` closes admission, blocks while a Reader is alive, and returns when it is released.
- **SESSION-02 — PASS in source-pin scope:** The helper and Gate APIs are the actual pinned native headers, with two additional pinned native source files guarding the reviewed Init/Shutdown and assembly-lock expressions. These source checks **do not** verify an actual full native TU build, runtime linker or Unity lifecycle.
- **SESSION-03 — OPEN / HIGH:** `std::mutex` is not actual `g_MetadataLock` or `s_assemblyLock`. The real `Assembly::TryVisitOriginalV1ExecutionImages` holds the latter internally and may be nested beneath the former. A production adapter needs **separate lock-order/deadlock/shutdown audit**, callback provenance and thread constraints. `Gate::CloseAndDrain` may wait indefinitely if actual VM locks or callbacks form a deadlock. This host's bounded tests do not prove real-world progress or lock latency.
- **SESSION-04 — OPEN / HIGH:** Admission at default `Reader.Epoch()==1` does not prove provenance or validity of borrowed images/metadata/classes, an atomic assembly/class/GC epoch, or safe support for reopening after Shutdown. The test verifies that the default Reader **rejects a reopened epoch 2**; it does not authorize using an explicitly stamped epoch 2 against existing process-lifetime registries.
- **SESSION-05 — OPEN / HIGH:** Both original physical scans are driven by the **same caller-owned synthetic source**. Matching passes do not independently prove it includes the full live physical registry, that all TypeDefs are first-owner eligible, or that any observed execution-use graph is complete. The conservative physical slot sum is not an exact used/unique TypeDef high water. Lane U and all pre-owner rejected/nonroot paths remain separate and unproven.
- **SESSION-06 — OPEN:** Runtime build/Player/GC/metadata cleanup, stack/RSS and real lock timings, complete V1 field14/15 byte parity, native V2 envelope/receipt/recovery and original independent R03 findings remain outstanding. **The native B2 128-combined TypeDef cap, 64-byte names and 65,536 owner lookup cap are unchanged.** No storage candidate has been selected or connected.

**Future change requiring independent Human Review Gate authorization:** Decide whether to add a physically scoped read-only source API after proving actual class/metadata allocation origin, exact `Reader` + `g_MetadataLock` + `s_assemblyLock` lock order under concurrent shutdown and assembly publication, exhaustive physical image admission/overflow semantics, bounded cost and independently receipted Local validation. Do **not** treat this host API as a ready-to-compile IL2CPP integration or use the consumed B1 oneuse-12 to authorize a new run.

**Disposition:** `PassedSyntheticReaderLockScopeOnly` at exact-code 4/4-success CI; all runtime and acceptance flags remain false. `WEB_TO_LOCAL=CLOSED_NO_LOCAL_EXECUTION`, `R03Accepted=false`, `H2Passed=false`, `ReadyForHumanReviewGate=false`, PureInterpreter disabled.
