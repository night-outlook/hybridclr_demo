## 3. Finding IR-D5BC10-RR-01 — HIGH / blocking: final receipt still depends on managed execution after terminal poisoning

**Evidence:** [`R03D5P5WindowPlayer.cs` lines 174–223](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/R03D5P5WindowPlayer.cs#L174-L223) executes `CommitTransaction()` and then calls `Thread.Join`, `GetState` and **`R03_D5_ReceiptSeal` from managed `finally``. [`R03D5WindowOverlay.cpp` lines 260–299](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/R03D5WindowOverlay.cpp#L260-L299) writes the native guard counters, reads the bound canary, captures native immutable first-error and seals **only when that managed call happens**; it requires `workerFinished==1`. The C10 negative case may poison process business execution during `method.Invoke`; the native terminal guard can prevent later AOT method entry. Merely implementing `ReceiptSeal` in C++ does not guarantee the managed-to-native call is reached.

The new `R03_D5_ReceiptOpen` correctly opens an exclusive file before Commit, but no native terminal-side producer, out-of-band completion mechanism or separately authenticated automatic finalization is implemented for the central denied/terminal path. If a managed follow-up is blocked, the receipt remains partial, and its parser returns `NoCoverage`. **That is fail-closed against false acceptance, but it is not a reliable measurement producer.** The prior Primary report itself identifies this uncertainty. Host tests intentionally compile without the actual VM branch, so their passing writer receipt does not close it.

**Independent decision on the requested question:** This is **not sufficient even for `PassD5BC10ForNextPreparation` as a reviewed, ready-to-validate C10 producer**. The key outcome cannot depend on executing post-terminal managed code with no proven fallback. Primary must design a bounded native terminal-fact recording/finalization path, or an independently testable source-proven out-of-band equivalent, that preserves first-error and does not allocate, block, or write files while metadata/usage/VM critical locks are held. Prove terminal and nonterminal receipts in focused source-host tests before the next rereview. Do not turn `NoCoverage` into a negative pass.

## 4. Finding IR-D5BC10-RR-02 — HIGH / blocking: no one-to-one join between the worker's target invocation and counted guard decision

**Evidence:** [`AssemblyShadow.cpp` lines 2381–2399](https://github.com/night-outlook/il2cpp_plus/blob/84f9435628b8ff4cc675409f6b4d76dd2753d8a8/libil2cpp/vm/AssemblyShadow.cpp#L2381-L2399) now restricts counters by **physical assembly name**, namespace, type name, and method name `Keep`. This is a real improvement: unrelated constructors no longer satisfy the **same-name** counter. However it does **not** identify an exact `MethodInfo` signature/instance or thread, and the [window header `MethodResult`](https://github.com/night-outlook/il2cpp_plus/blob/84f9435628b8ff4cc675409f6b4d76dd2753d8a8/libil2cpp/vm/AssemblyShadowD5WindowProbe.h#L124-L151) aggregates **all matching invocations during P5**. The managed [worker's `keepAttempted` flag and slot-4 event](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/R03D5P5WindowPlayer.cs#L76-L117) are not attached to a native method-entry token; the canary binds one object, but method counts are process-wide.

If another matching `R03.Node.Keep` call occurs during P5, its guard result could be joined to this worker's slot-4 attempt and the worker-bound object's unchanged canary. This is **a source-supported ambiguity**, not an observed second call in a Player. Current tests supply synthetic `MethodResult(true/false)` directly and do not prove unique producer attribution. A robust C10 negative case must join the **same invoked method and worker** to its guard decision and bound target object, or independently prove there cannot be a competing matching call. Add a negative regression with a concurrent second `Keep` call or mismatched attempt token; verify it cannot classify as the worker's denied Keep.

## 5. Finding IR-D5BC10-RR-03 — MEDIUM / source-parser defect: a missing completion event can still yield a denied candidate

**Evidence:** [`d5_c10_native_receipt.py` lines 19, 78–101](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/d5_c10_native_receipt.py#L19-L101). `REQUIRED=(1,2,3,4,6,7,8,9,10)` **omits event slot 5**, which [`R03D5P5WindowPlayer.cs` lines 99–117](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/R03D5P5WindowPlayer.cs#L99-L117) uses for `method.Invoke` completion/exception. This does not authenticate any forged real Player evidence (the parser still sets `realPlayerC10Passed=false`). Require slot 5 and verify its explicit status/relationship to native guard and worker completion, or explicitly separate a justified noncompletion case with a different result; add `material(events=[5])` negative regression to [`test_d5_c10_native_receipt.py`](https://github.com/night-outlook/hybridclr_demo/blob/063de11e2459fa6530dee0bd0da9176f14b15c7f/Tools/AssemblyShadow/R03IR/D5Probe/test_d5_c10_native_receipt.py).
