## 1. Source-grounded problem

The **actual inactive native** `libil2cpp/vm/AssemblyShadowBoundedDefinitionExecutionLiveSource.inl` collects a restricted execution TypeKey subset inside the initial `assembly_shadow_metadata_lifetime::Gate::Reader` and `g_MetadataLock`. It obtains an **original V1 token-valid physical image inventory**, including interpreter images, in original registration order via `Assembly::TryVisitOriginalV1ExecutionImages`. This is different from registered AOT-only image inventory and logical Assembly visibility. Original first-owner means the first image whose indexed TypeDef handle matches, as in `AssemblyShadowOriginalV1OwnerJoin.h` and the legacy field15 first-emplace behavior.

Actual owner resolution (`resolveOwner`, approximately lines 620–725) independently checks this first original-V1 owner **before** calling `NonRootOwnerAudit::Note`. `Note` has a **combined limit of 128 distinct root+nonroot handles**, and the earlier root-only preflight stops at 129. `buildDefinition` follows declaring ancestry and explicitly supplies root/nonroot roles; nested/generic/composite/primitive argument paths may reenter it. Some unsupported/rejected paths terminate before resolving owners or before recording a complete declaration. Therefore:

- Recording only **after** `NonRootOwnerAudit::Note` creates a cap-biased census. Raising 128 in that object without an observed high-water/stack budget is not acceptable.
- Recording only within existing successful `resolveOwner` visits still misses **earlier rejected and entirely unvisited TypeDef paths**. Absence of failures does not establish full field15 or whole-VM coverage.
- A separate original-physical-owner source observer is the better *future design candidate* for a representative population census, provided its exhaustive traversal and input lifetime can independently be proven. **No such observer exists today.**

## 2. This cycle's bounded implementation

Added only to `night-outlook/hybridclr_demo`:

- `Tools/AssemblyShadow/R03IR/TypeDefCensus/OriginalV1OwnerSourceAdapter.h`: small C++11 source-host adapter layered over the existing **test-only** `BoundedNativeCensusProducer`. A caller passes an array of `ImageView` synthetic token-valid physical images (type handle arrays, image and assembly tokens), an explicit `Observation` (opaque handle, expected owner ordinal, claimed first-owner ordinal, explicit root or nonroot use role, length-only declaration facts) and a caller-selected indexed-lookup budget. The adapter independently scans **the supplied original image order**, uses the first matching handle, rejects owner mismatches, then calls the existing recorder's `Add`. Every image header is checked, including slots later than the first owner. `AddUse` stores no raw image/handle pointer, performs no allocation, file IO, formatting or string copies, and counts at most a caller-bounded number of handle lookups.
- `OriginalV1OwnerSourceAdapterHost.cpp`: standalone mock-source regression and complete/incomplete JSON fixture driver. Never include in a Unity or libil2cpp production compilation roster.
- `.github/workflows/r03-b2-original-v1-owner-source-host.yml`: macOS/Linux × C++11/C++17, strict and ASan/UBSan, plus cross-check of both fixture variants using the previously checked-in Python `analyze_typedef_census.py`.

`Open` accepts at most **1,024 synthetic images** and **1,000,000 total indexed lookups** in this experiment. Each image is limited to 8,192 indexed handles. The underlying producer still has **1,024 distinct handle / 4,096 event** prototype limits. These bounds are independent from the live B2 128-handle and 65,536-lookup limits, but **do not establish real-game high-water or accepted future bounds**. Overflow, missing handles, first-owner disagreement, a malformed image, failing producer, unsupported path or abandoned open capture produces an incomplete lower bound; failures revoke the producer's `Complete` state and scrub its opaque pointer-key index.

The adapter never sets Unity, VM epoch, independent authentication, native V2 or product-acceptance flags. All emitted JSON remains `captureKind=UnverifiedSource`. `CloseAfterSource` is documented as callable **only after** real metadata protection has exited, but this host mock has no actual `g_MetadataLock`, runtime lifetime Reader or source-callback identity. Caller-supplied token fields and image arrays are **not** verified real VM evidence.

## 4. Primary review findings and blocking gaps

- **SEAM-01 — PASS in synthetic host scope:** First-owner selection uses original image enumeration order, **not** AOT-only membership or last match. A later duplicate cannot override an earlier owner. Explicit role event reporting remains independent of the handle's identity.
- **SEAM-02 — PASS in synthetic host scope:** Invalid/contradictory image headers and owner ordinals, capped index budget, missing handle and abandoned collection all reject without publishing a complete result. No allocation in `AddUse`; output formatting happens through the existing producer after capture closes.
- **SEAM-03 — OPEN / HIGH:** The image arrays and expected owner ordinals are entirely synthetic. No actual `MetadataCache::GetAssemblyTypeHandle`, physical `Il2CppImage` owner backlink, class registry identity, `g_MetadataLock`, `MetadataLifetimeGate.Reader` or original `CopyValidAssemblies` callback is bound to this adapter. Caller assertions are not source provenance. A real native attachment is a **separate architecture change requiring explicit review**.
- **SEAM-04 — OPEN / HIGH:** There is **no independent exhaustive traversal of root+nonroot TypeDef use sites**, especially rejected/generic/nested/primitive and unseen classes. The adapter can only flag an omission explicitly reported by its caller. Even a structurally complete trace is not evidence of full original execution field15 or a coherent class/metadata/GC/VM lifetime epoch.
- **SEAM-05 — OPEN / HIGH:** Repeated original-image scanning is O(events × images × TypeDefs) in the worst case, with a **1,000,000-read test budget only**, and no real metadata-lock latency/RSS/worker-stack/GC measurement. Current native B2 has independent 65,536 lookup and 128-handle limits. Neither candidate storage nor future capacity is selected.
- **SEAM-06 — OPEN:** Calls to `MarkUncovered` can invalidate a previously completed *in-memory* producer, but cannot retract a string/file already emitted. Any future native design must make completeness and image/callback source proofs final **before** serialization and independent receipt sealing. Full original V1 fields14/15, native V2, external readback, first recovery, real Unity Player and the historical full-stage R03 FAIL/High findings remain unresolved.
