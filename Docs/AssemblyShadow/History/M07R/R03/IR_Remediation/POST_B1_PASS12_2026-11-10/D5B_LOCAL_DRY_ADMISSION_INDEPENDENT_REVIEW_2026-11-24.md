## 3. Blocking source findings

### D5B-DRY-IR-01 — HIGH: direct receipt sealer does not authenticate its approval envelope

**Source:** [`approved_envelope(raw)` lines 393–435](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L393-L435) verifies a complete frozen Git-blob hash and mandatory `independentExecutableAdmissionReview`, `userLocalExecutionApproval`, four source pins, all historical paths, Unity SHA and scope. But [`seal_oneuse_dry_admission(approved, admission)` lines 478–490](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L478-L490) only requires **`APPROVED_EXECUTION_ENVELOPE_BLOB is not None`**, then accepts **caller-provided dicts** and calls `oneuse_receipt`. It does **not** call `approved_envelope` or prove the supplied approval dict is the exact independently reviewed record. This means merely making the constant non-null in a future code revision would allow a *direct caller* to synthesize a receipt without meeting the reviewed/user envelope semantics. The normal public CLI currently does validate first; this finding is a **future API/custody-boundary defect**, not an observed bypass of today's closed CLI.

**Reproducible evidence already present in the exact passing test source:** [`test_35_oneuse_output_exclusivity_and_no_player`](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/test_d5b_local_admission.py#L385-L408) creates `fake_approval = self.fake_approval()` (lacks required `schemaVersion`, independent review/user approval fields), temporarily patches the constant to the Git blob of a **different valid synthetic envelope** and calls `seal_oneuse_dry_admission(fake_approval, fake_admission)`; the test **passes and creates receipts**. Thus the sealer accepts an unreviewed approval dict even when an approval-hash constant exists. By contrast, `test_53` proves only the **None** anchor blocks the direct sealer. No real Local execution was performed.

**Required Primary correction:** make the only receipt-writing entry consume verified **raw frozen envelope bytes** (or a non-forgeable internally created result tied to those bytes) and run `approved_envelope()` at the writer boundary; reject any dict that was not obtained from that exact envelope. Do not rely on comments saying the caller should have checked it. Add regression that patches a *test-only* approval anchor and passes a mismatched/unauthenticated dict; it must fail **without creating output**, while the exact valid test envelope can still pass. Retain current production anchor None.

### D5B-DRY-IR-02 — HIGH: no source/output custody revalidation at the write boundary or postflight

**Source:** [`inspect()` lines 362–389](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L362-L389) validates canonical roots, source/live remote, Original S, output parent and host at the **time of inspection**. [`main()` lines 525–544](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L525-L544) then passes its snapshot to `seal_oneuse_dry_admission`. The sealer checks **only** that the string path `root` is absent and not a symlink, then executes `root.mkdir()` and writes files. It does **not** re-check the approved parent/source/historical root, live refs, clean HEADs, output parent canonicality or source bytes immediately before writing; nor does it perform the promised postflight source/authority check before returning `DryAdmissionRecorded_NoUnityOrPlayer`. A parent-directory replacement or source ref/worktree change between `inspect` and `seal` can result in a receipt at a stale or newly aliased location. A direct caller can skip `inspect` entirely (also IR-01).

**Repro path:** in a *temporary, synthetic filesystem* with test-only approved anchor, construct valid `approved`/`admission` values, complete or mock a positive `inspect`, then change the evidence parent to a symlink pointing into a protected historical/source root, or mutate the pinned source HEAD/worktree, before `seal_oneuse_dry_admission`. The current sealer has no checks capable of noticing this change; `root.mkdir` follows the current parent path. This is a **source-derived** counterexample, not an executed real Local run. The [Primary design §5, stage 4](D5B_LOCAL_DRY_ADMISSION_DESIGN_2026-11-24.md) explicitly requires rechecking authority and source after dry admission, which is not implemented.

**Required Primary correction:** revalidate approved source+historical+destination custody **inside the approved one-use write boundary**, including exact live remote/local heads and physical parent identity, and perform a fail-closed **postflight** source/custody check before any success verdict. Preserve the one-use output and any partial negative evidence if a check fails; do not retry/overwrite. For directory-link/rename races, bind the destination to a verified physical parent (directory handle / no-follow creation or equivalent on macOS), not merely the previous path string. Add synthetic regression for source drift between inspection and write, evidence-parent alias/replacement and postflight failure; no positive admission receipt may be emitted.

### D5B-DRY-IR-03 — MEDIUM: partial output creation is misreported as `outputCreated=false`

**Source:** [`seal_oneuse_dry_admission` lines 486–516](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L486-L516) creates the one-use root before writing four outputs. There is **no** failure receipt/partial-output marker if writing `ADMISSION.json`, `CELLS.json`, `LOCAL_BATCH_RESULT.json` or `MANIFEST.json` raises (e.g. disk full, permission error, serializing an unexpected type). [`main` catch lines 552–563](https://github.com/night-outlook/hybridclr_demo/blob/2d0039192d1264d5799411668acd7e911b28b830/Tools/AssemblyShadow/R03IR/D5Local/d5b_local_admission.py#L552-L563) unconditionally claims `outputCreated: false` even if a prior `root.mkdir` already succeeded. The output is then consumed/partially present while the returned status falsely claims no output.

**Repro path:** under a synthetic test-only anchor, mock `write_exclusive` to raise `OSError` on the first or third write **after** `root.mkdir` and invoke the future execute path. Current `main` catches that exception and returns JSON with `outputCreated=false` while `candidate.exists()` is true. This defect is not reached by the currently disabled public CLI; the 53 green tests cover only successful synthetic sealer writes and pre-creation denials.

**Required Primary correction:** track whether the root was created and which exclusive receipts exist; report a truthful `FailedAfterPartialOutput`/`outputCreated=true` with immutable partial evidence or an independently auditable failure marker. Preserve consumed one-use identity and do not overwrite/retry. Add fault-injection tests at each output write, including a write failure after the third receipt, and verify the caller's reported `outputCreated` and file ledger match physical state.
