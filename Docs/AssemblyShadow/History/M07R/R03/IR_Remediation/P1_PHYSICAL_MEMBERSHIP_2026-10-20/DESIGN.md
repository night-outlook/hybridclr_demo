## Bounded native code

- `libil2cpp/vm/AssemblyShadowPhysicalMembership.h` owns a one-use scratch object containing 2,048 opaque pointer slots, source witness role bytes, matched flags and a registry-only revision; maximum 1,024 observed identities, 65,536 iterator callbacks and a `sizeof(Scratch)<=24576` compile-time cap. No heap-backed buffers or stored pointer values survive `Scrub()`.
- First copy is taken under the original short `ExecutionObservationLock` while holding one initial-session-only `MetadataLifetimeGate::Reader`. Every slot must match the existing write-once Candidate/ActiveShadow witness table, the observed count must fit, and the revision must not be saturated. After releasing the lock, require uniqueness of observed identities.
- If observed count is nonzero, acquire `g_MetadataLock` but **NOT** the execution observation lock and call the original native `il2cpp_class_for_each` (not a custom class enumerator). The synchronous callback compares only pointer **values**, using the same fixed open-addressing layout, and counts matched registered identities once. Unrelated/duplicate classes are harmless; null callbacks, iteration overflow, or an incomplete observed subset reject the capture.
- After releasing `g_MetadataLock`, reacquire the short observation lock to verify the entire slot array, exact witness roles, count and registry revision are unchanged. Reject observed active/state publication changes. This read-fence still cannot detect all possible ABA or unrelated VM mutations; it must not be presented as a coherent global epoch.
- `AssemblyShadowPhysicalMembershipSource.inl` implements the real, **uncalled** `AssemblyShadow::TryAuditObservedPhysicalClassMembership(Scratch&,Receipt&)`. It returns only observed/enumerated/matched **counts**, revision numbers and explicit scope booleans. `physicalClassPointerOriginProven`, `metadataPointerLifetimeProven`, `coherentVmEpochProven`, `executionJsonComplete`, `playerExecution` and `runtimeAcceptance` are always false.
- No original `GetExecutionDiagnosticsJson`/`GetDiagnosticsJson` body, active caller, registration writer, class metadata field, type-key builder, C# API or V2 transport changes. The implementation is **inactive**, and membership cannot authorize a later pointer dereference.

## Admission/locking and technical limitations

Order is metadata lifetime Reader → short registry copy/unlock → physical iterator under metadata lock/unlock → short registry verify/unlock → Reader release. Never nest metadata/observation locks or call managed code inside them. The original iterator's own allocation, time, callback count, class cache contents and Shutdown lock interactions are **not proven** by host mocks; the 65,536 callback limit is a validation limit, not a hard runtime iteration time limit. A complete enumeration match merely confirms all observed opaque addresses appeared in that iteration. It does not prove the pointer allocator/owner, metadata lifetime after releasing the lock, generic-class coverage, a globally atomic epoch or ABA freedom. A non-enumerated interpreted/generic class must fail closed rather than being silently accepted as `classes:[]`.
