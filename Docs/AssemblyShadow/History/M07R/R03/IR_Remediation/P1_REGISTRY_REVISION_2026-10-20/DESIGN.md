## Production source and lock contract
- `libil2cpp/vm/AssemblyShadowExecutionRegistryRevision.h` introduces a fixed-size, nonallocating `Revision` with default zero, `Current()` and saturating `Advance()`. It is non-atomic by design: reads and writes must occur **only while holding the existing `ExecutionObservationLock`**. No extra lock or memory allocation is introduced.
- `AssemblyShadow.cpp` stores one process-lifetime registry revision beside the existing 2,048-slot table and 1,024-entry count. Every **successful new insertion** increments the revision under the same existing lock after incrementing the observed count. Duplicate and rejected registrations do not increment it. Saturation is sticky; future opaque captures reject the saturated value instead of claiming unobservable wraparound safety.
- `AssemblyShadowOpaqueExecutionInventory.h` records the revision in both fixed-size snapshots; a MAX revision is invalid. Its `SameAs()` requires equal revisions as well as identical occupied pointer slots and count. `Clear()` removes revision and pointer-value scratch before return. `Receipt.registryRevisionBefore`, `.registryRevisionAfter`, `.registryRevisionFenceStable` expose only numbers/boolean, never a class pointer or type key.
- `AssemblyShadowOpaqueExecutionInventorySource.inl` takes both revision samples **under the existing execution-observation lock**, within one metadata-lifetime admission. It fails closed on an observed revision change, invalid registry, nonunique pointer identities, state/active generation change, saturated version, scratch reuse, or unequal slots. Success marks only a **registry-only observed fence**, never a VM-wide epoch or provenance claim.

## Review limits, cost and rollback
The revision costs one saturating integer update per newly published observed class, on the existing observation lock. No change to hot-path duplicates, source registry capacity, IL2CPP image/type identity, managed APIs or original JSON getter. The new revision does not observe changes to class fields/GC/cctor state or uninstrumented writes, does not guarantee ABA freedom outside registered insertions, and does not prove native teardown lock safety. The original O(n²) bounded duplicate scan remains; no process RSS/latency proof is claimed.

Rollback is a conventional fast-forward code revert of this additive source revision after a separate review; never alter historical PASS/FAIL evidence or native pins in earlier manifests.
